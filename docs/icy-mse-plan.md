# План: название трека из потока (ICY) через собственный плеер на MSE

Статус: **этап 0 (спайк) написан**: `tools/icy-mse-spike.html`; остальное ещё нет. Основание: `tools/icy-probe.html` у владельца показал, что `ice4.somafm.com`
отдаёт ICY-метаданные браузеру (CORS разрешён, `Icy-MetaInt` виден, названия приходят и меняются).
Условие: звук играет с сервера только если запрос идёт **без `Referer: localhost`** (уже исправлено
в `index.html` и `vercel.json`).

## Цель и критерии успеха

1. Название трека меняется в момент, когда трек зазвучал (допуск ≈ 1 с), без опроса API.
2. Одно соединение на слушателя (как сейчас). Никаких дополнительных потоков.
3. Всё, что уже работает, не ломается: зеркала и переподключение, сторож, плавная громкость и затухание,
   восстановление канала без автозапуска, Media Session, визуализатор.
4. Там, где MSE недоступен или что-то пошло не так до первого звука, плеер сам откатывается на нынешний
   `<audio src>` с опросом API. Пользователь потери функций не замечает.

Не цели: свой декодер, поддержка AAC/AAC+ (берём `mp3`, он у всех каналов), запись, перемотка.

## Как это устроено (идея)

```
fetch(stream, Icy-MetaData: 1) ── байты ──► ICY-демультиплексор ──► аудио-байты ──► SourceBuffer('audio/mpeg')
                                                   │                                          │
                                                   └── метаданные (название, позиция) ───────► очередь «показать, когда время дойдёт»
<audio src="blob:…MediaSource"> ── GainNode (громкость/затухание) ── визуализатор / колонки
```

- Звук по-прежнему играет `<audio>`, только его `src` теперь `blob:` от `MediaSource`. Поэтому события
  элемента (`playing`, `waiting`, …), `GainNode`, визуализатор и Media Session продолжают работать.
- Бонус: `blob:` не требует CORS для звука, `crossorigin` на элементе станет не нужен.
- Синхронизация: метаданные стоят между аудио-блоками. Перед каждым блоком запоминаем позицию в
  медиа-времени (конец `buffered` после добавления предыдущего куска) и показываем название, когда
  `currentTime` её достигнет. Точность ≈ длина куска (сотни миллисекунд).

## Этапы (каждый заканчивается зелёными тестами и коммитом; до этапа 3 пользователь ничего не замечает)

### Этап 0. Спайк и решение «идти / не идти» (одноразовая страница, не продакшен)
- `tools/icy-mse-spike.html`: играет канал через fetch → ICY → MSE, показывает название и задержку.
- Проверяет **у владельца в его браузере**: звук без щелчков, пауза/Play, 15+ минут непрерывно (память,
  дрейф к «живому краю»), поведение при обрыве, совпадение названия со слухом.
- Критерий «идём»: звук стабилен 15 минут, название совпадает с тем, что слышно. Иначе: останавливаемся на
  опросе API (потрачен один этап).
- Дополнительно: `MediaSource.isTypeSupported('audio/mpeg')` в Firefox, Safari (macOS) и iPhone
  (`ManagedMediaSource`): уже выводит `icy-probe.html`.

**Этап 0: статус.** Страница готова и проверена в Chromium на локальном ICY-сервере с настоящим MP3
(`ffmpeg`, `metaint=16000`, стартовый «всплеск» 3 с, реальный темп): звук идёт, названия показываются в
такт звуку (позже, чем приходят из потока, на размер буфера, 1–7 с), буфер обрезается, ошибок нет,
одно соединение, память ~10 МБ. На реальном SomaFM из облачной среды проверить нельзя (403 даже
честному headless-Chromium). **Нужна проверка у владельца в Chrome и Firefox**: `npm run dev`,
`http://localhost:3000/tools/icy-mse-spike.html`, «Старт», слушать 15+ минут, в конце «Отчёт».
Сверка по пунктам: звук без щелчков и провалов; пауза/Play; название совпадает со слухом;
в отчёте `waiting`/`stalled` близки к нулю, память не растёт.

### Этап 1. `src/lib/icy-demuxer.ts` (чистая логика + тесты)
- Разбор потока `metaint` байт аудио → 1 байт длины (×16) → метаданные → повтор; границы кусков в любом месте.
- Разбор `StreamTitle='…';` (кавычки внутри названия, пустые блоки, длина до 4080 байт), кодировка
  UTF-8 с запасным вариантом windows-1252, «Artist - Title» → два поля.
- Тесты: случайное дробление потока (fuzz), блок на границе куска, нулевая длина, повреждённые данные.
  Логика уже отлажена в `tools/icy-probe.html`, переносим.

### Этап 2. `src/lib/mse-stream.ts` (воспроизведение)
- `MediaSource` + `SourceBuffer('audio/mpeg')`: очередь добавления (по одному, `updateend`), ограничение
  скорости чтения (не читаем дальше, чем на 20 с вперёд), обрезка старого (`remove` всё старше
  `currentTime − 30 с`), `QuotaExceededError`, возврат к «живому краю», если отстали больше 15 с.
- События наружу: `playable`, `metadata(title, mediaTime)`, `lost(reason)` (сетевой обрыв, конец потока,
  ошибка декодера). Полная очистка (`abort`, `revokeObjectURL`, закрытие `reader`).
- Тесты: фейковые `MediaSource`/`SourceBuffer` (порядок, обратное давление, обрезка, ошибки) и браузерный
  прогон в Playwright на локальном ICY-сервере (у нас уже есть сервер с burst и сбросами; валидные «тихие»
  MP3-кадры собираем вручную).

### Этап 3. Транспорт в `usePlayer` (рефакторинг без смены поведения, затем MSE за флагом)
1. Выделить интерфейс `StreamTransport { start(url) ; stop() ; on(lost|playable|metadata) }` и
   `ElementTransport` (то, что есть сегодня: `element.src`). Все 140 тестов остаются зелёными.
2. Добавить `MseTransport` поверх этапа 2. Выбор транспорта: определение возможностей
   (`MediaSource`, `isTypeSupported`, потоковый `fetch`) + аварийный выключатель
   (`localStorage['somafm-player:transport']` или `?transport=audio`).
3. Подключить к существующим механизмам без их переписывания: зеркала и переподключение (`lost` вместо
   `error`), сторож по `currentTime`, затухание перед сменой источника, отложенный старт (`autoplay=false`
   не открывает соединение до Play), долгая пауза (новое соединение с «живого края»).
4. Откат: если MSE упал **до первого звука**, сразу переключаемся на `ElementTransport` для этого канала.

### Этап 4. Название трека из потока
- Store: `liveSong` (из ICY) поверх `songs[0]` из API. Показываем по таймлайну синхронизации.
- Политика опроса API: пока ICY живой, не опрашиваем (экономия запросов); при потере ICY или при откате
  на `<audio>` опрос включается как сейчас. История треков и обложка остаются из API (один запрос при
  выборе канала).
- Media Session и заголовок вкладки берут `liveSong`. Рендер только как текст (без `v-html`).

### Этап 5. Выкатка по ступеням
1. Флаг выключен по умолчанию; включение `?transport=mse` для проверки владельцем.
2. Матрица ручной проверки: Chrome и Edge (Windows), Firefox, Safari (macOS), iPhone Safari 17.1+,
   Android Chrome. Что смотрим: старт, пауза/Play (без щелчков), смена канала, обрыв сети, 30 минут игры.
3. Включить по умолчанию там, где проверено; остальным оставить `<audio>`.

### Этап 6. Безопасность и документация
- CSP: `media-src` дополнить `blob:` (иначе `MediaSource` не будет играть); `connect-src` уже разрешает
  `*.somafm.com`.
- `HANDOFF.md`, тесты в CI, инструкция отката (выключатель транспорта).

## Что остаётся без изменений
Зеркала из `.pls`, правила доверенных хостов, затухание/громкость на `GainNode`, визуализатор, восстановление
последнего канала, кэш каналов, Media Session, CI.

## Риски и как их снимаем

| Риск | Вероятность | Что делаем |
| --- | --- | --- |
| MSE плохо принимает произвольно нарезанный MP3 в каком-то браузере | средняя | Этап 0 (спайк) в браузере владельца; нарезка по границам MP3-кадров, если нужно |
| iPhone (нужен `ManagedMediaSource`, фоновое воспроизведение, экран блокировки) | высокая | Там остаётся `<audio>` + опрос API, пока не проверено на устройстве |
| Дрейф задержки, рост памяти за часы игры | средняя | Обрезка буфера и возврат к «живому краю», тест на 30+ минут |
| SomaFM изменит правила (CORS, `Referer`, лимиты, формат метаданных) | низкая | Автооткат на `<audio>`; выключатель |
| Двойная нагрузка на сервер при ошибках | низкая | Одно соединение; переподключения ограничены тремя попытками |
| Сложность: больше кода в ядре плеера | высокая | Транспорт за интерфейсом; старый путь остаётся рабочим и покрыт тестами |

## Оценка объёма (грубо)
Этап 0: ~1 сессия (+ ваше время на проверку 15 минут). Этапы 1–2: ~1–2. Этап 3: ~1–2. Этапы 4–6: ~1.
Итого 4–6 рабочих сессий, с точкой «стоп» после этапа 0 и после этапа 5 (шаг 2).
